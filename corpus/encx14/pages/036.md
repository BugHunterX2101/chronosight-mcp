# 36 CMD register and OTP

## 36.1 CMD (0x30, W)

  Value    Command
  0xA5     Soft reset
  0x80     Burn OTP (CONF1, ZPOS, MPOS)
  others   Ignored

## 36.2 Soft reset

Writing 0xA5 to CMD resets the device. The effect is identical to a
power-on reset (page 11): CONF2 = 0x00, STATUS.RST = 1, CONF1, ZPOS and
MPOS reloaded from OTP. The device does not acknowledge the data byte of
the soft-reset write; a NACK on that byte is expected.

## 36.3 OTP burn

Writing 0x80 to CMD copies the current CONF1, ZPOS and MPOS register values
into OTP. The burn takes 10 ms. Do not access the device during the burn.

Requirements:

  - VDD between 3.2 V and 3.6 V during the burn (errata E-1, page 57).
  - The burn can be done only once. A second burn command is ignored.
  - CONF2 cannot be burnt. FILT, DIR, HYST and WD must always be written by
    the host after a reset.

## 36.4 Verifying the burn

1. Write 0xA5 to CMD (soft reset).
2. Wait 2 ms.
3. Read ZPOS, MPOS and CONF1 and compare them with the intended values.
4. Read STATUS and confirm RST = 1 (the soft reset was seen).

## 36.5 Why CONF2 is not in OTP

CONF2 controls behaviour that a host may need to change at run time (for
example a stronger filter at standstill). Keeping CONF2 volatile allows
this, at the cost that the host must rewrite CONF2 after every reset.
