# 30 ZPOS and MPOS (zero and maximum position)

## 30.1 ZPOS (0x03-0x04, RW, OTP shadow)

  Register   Bits   Field         Description
  ZPOS_H     5:0    ZPOS[13:8]    Zero position, high bits
  ZPOS_L     7:0    ZPOS[7:0]     Zero position, low bits

ZPOS is subtracted from the filtered angle before it is written to ANGLE.
Write ZPOS_H first, then ZPOS_L. The new zero takes effect after the write
to ZPOS_L.

## 30.2 MPOS (0x05-0x06, RW, OTP shadow)

  Register   Bits   Field         Description
  MPOS_H     5:0    MPOS[13:8]    Maximum position, high bits
  MPOS_L     7:0    MPOS[7:0]     Maximum position, low bits

When MPOS is less than 0x3FFF, ANGLE is scaled so that the range from ZPOS
to MPOS spans the full 14-bit output. The default 0x3FFF gives a full
360° range with no scaling.

## 30.3 Scaling and noise

Scaling a small range to the full output also scales the noise. For a
90° range (MPOS = 4096) the noise in ANGLE is four times the noise in RAW,
expressed in output codes. Noise expressed in degrees is unchanged.

## 30.4 Programming ZPOS and MPOS permanently

ZPOS and MPOS written over I²C are volatile until burnt into OTP. A reset
reloads them from OTP. To make them permanent, use the OTP burn command on
page 36. OTP can be burnt only once.

## 30.5 Host-side alternative

Many hosts keep ZPOS = 0 and MPOS = 0x3FFF and apply the offset in
firmware. This avoids OTP programming in production and avoids surprises
after a reset.
