# 41 Address auto-increment and wrap

## 41.1 Auto-increment

The register pointer increments after every byte in both read and write
transactions.

## 41.2 Wrap rules

  Pointer after    Next pointer
  0x0F             0x0B by design; 0x10 on all silicon (errata E-4)
  0x1C             0x00
  0x30             0x30 (CMD does not auto-increment)
  reserved         next address

## 41.3 Intended wrap after 0x0F

The output block 0x0B-0x0F was designed to wrap back to STATUS (0x0B) so
that a host could read STATUS, ANGLE and RAW continuously in one long
burst. On all silicon the pointer moves to 0x10 instead (errata E-4, page
59), and the byte read from 0x10 is undefined.

## 41.4 Recommended practice

  - Never rely on wrap. Start every transaction with an explicit pointer.
  - Keep burst reads within 0x0B-0x0F.
  - For long logging captures, issue one 5-byte burst read from 0x0B per
    sample.

## 41.5 Write auto-increment across CONF2

A multi-byte write starting at 0x06 runs through the reserved address 0x07
and into CONF2 at 0x08. Avoid writes that span 0x06-0x08; an unintended
byte in CONF2 changes FILT, DIR, HYST or WD.
