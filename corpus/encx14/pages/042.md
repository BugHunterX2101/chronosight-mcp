# 42 Bus error recovery

## 42.1 Stuck bus

If the host is reset in the middle of a read, the device may hold SDA low
while it waits for clock pulses to finish a byte. To recover:

  1. Configure SCL as a GPIO output and SDA as an input.
  2. Toggle SCL up to 9 times until SDA reads high.
  3. Generate a STOP condition.
  4. Return the pins to the I²C peripheral.

## 42.2 NACK on the address byte

A NACK on the address byte means the device is not responding. Causes:

  - The device is in reset (power-on, brown-out, watchdog, soft reset). It
    responds again 1.5 ms after the reset (page 11).
  - The ADDR pin changed state before the last reset (page 13).
  - TEST is not tied to GND (page 9).

After the device responds again, read STATUS. If RST = 1, rewrite CONF2.

## 42.3 Wrong data

If CHIP_ID does not read 0x14, the bus is corrupted or a different device
answers. Check pull-ups and cable length (page 17).

## 42.4 A reset during a transaction

A reset that occurs in the middle of a transaction aborts it. The host sees
a NACK or a byte of 0xFF. The next successful read of STATUS shows RST = 1.

## 42.5 Recovery is not configuration

Bus recovery restores communication. It does not restore CONF2. After any
recovery, read STATUS and rewrite CONF2 if RST = 1 (page 45).
