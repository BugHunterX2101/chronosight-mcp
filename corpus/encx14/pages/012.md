# 12 Timing, read latency and phase lag

## 12.1 Internal timing

  Parameter                                 Typ     Max     Unit
  Internal sampling period (8 kHz)          125     125     µs
  CORDIC processing delay                   60      80      µs
  Register update period (ANGLE, RAW)       125     125     µs

## 12.2 Read latency seen by a host

The angle that a host receives is older than the moment the read
completes. The age is the sum of the internal processing delay, the time
since the last register update, the I²C transfer time and the time the host
firmware takes to service the transfer.

For the typical case of a host running a 1 kHz control loop that starts one
3-byte burst read (page 40) per control period at 400 kHz, and that uses the
value in the next control step, the effective latency is two control
periods.

**The I²C read latency is 2 ms for a host that polls once per 1 ms control
period and uses the result in the following period.**

Model the encoder in simulation as a pure delay of 2 ms on the true angle,
followed by the FILT filter and the output noise.

## 12.3 Phase lag

A pure delay T adds a phase lag of 360° x f x T at frequency f. The FILT
filter adds atan(2 x pi x f x tau). Table 12-1 lists the total phase lag
for the 2 ms latency case.

Table 12-1. Phase lag from a 2 ms delay plus the FILT time constant.

  Frequency   FILT=0     FILT=3 (1 ms)   FILT=5 (4 ms)   FILT=7 (16 ms)
  1 Hz        0.7°       1.1°            2.2°            6.5°
  4 Hz        2.9°       4.3°            8.6°            24.8°
  10 Hz       7.2°       10.8°           21.3°           52.4°
  30 Hz       21.6°      32.3°           58.6°           93.2°

A joint loop with a crossover between 3 and 10 Hz tolerates FILT = 3 with
almost no extra phase lag. FILT = 7 costs about 25° at 4 Hz and can make a
loop that was stable with FILT = 0 oscillate. See page 49.
